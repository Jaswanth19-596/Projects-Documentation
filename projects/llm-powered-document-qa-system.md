## Learnings

- **approach:** How are you identifying the document type?

  1. We will be checking the S3 key which contains the document folder structure.
2. The fallback approach is that we will be checking the content of the document, a part of the content, and then figure out the domain it belongs to. 


The purpose of identifying the document type: 
1. It helps to attach the document type for each chunk as the metadata. 
2. This helps us to perform: Pre filter which reduces the search space, eliminates answers from different domains.
3. Helps us to chunk different documents differently, provide different system prompts per category.
4. Helps us to control who can access which documents. 
5. Helps us to identify which document type queries are more costly. 


1. Different documents need different parsing strategy, chunking strategy.

- **approach:** How are we identifying sections in markdown files

  We used regex pattern matching to identify markdown headers. 

What we detect: Any line starting with 1-6 # characters followed by a space. 

What we extract: The header text, and the character offset - so the downstream chunker knows exactly where each semantic boundaries starts. 

Why we run it on stashed text: Code blocks are replaced with __CODE_N_ placeholders before section extraction runs. This prevents the # inside a  code block from being misidentified as a heading. 

- **skill:** Difference between Vector Index, Vector Store, Vector Database

  1. Vector Index: It is the underlying LlamaIndex data structure that performs chunking, embedding, storing.
2. Vector Store/Vector Database: it provides basic functionality like index + Storage. They both are used interchangebly.  Ex: Pinecone, Chroma etc

- **skill:** Why don't we use Pinecone for both vectors and Chunks

  When you only provide vector store and no document store, then Pinecone serializes the chunk text into Pinecone's metadata field, alongside the embedding. So one pinecone record contains: Vector, text, any metadata.

Advantages:
- Single source of truth.
- No need of doc store.

Dis:
- Limit is 40KB per vector, more text gets truncated.
- Not optimized for text storage. 
- If you update document, you have to delete and reupsert vectors.

- **skill:** What are response modes in Llama index

  Most of the times, when you retrieve chunks, you don't dump them directly into a LLM call. 

You either want to  summarize, sometimes you want direct answer, sometimes you want LLM to reason over each chunk individually.
